# 창의디자인캠프 Windows 배포판 (인스톨러 + 런처) — 설계

작성일: 2026-08-21
대상 행사: 2026 영남·제주권역 창의디자인캠프 (2026-09-19~20)
선행 문서: `2026-08-21-camp-opencode-preset-design.md` (프리셋, 구현 완료)

## 1. 배경

프리셋(에이전트 4종 · 한국어 명령어 10종 · 스킬 4종 · 발표자료 템플릿 ·
크레딧 강제 래퍼)은 구현이 끝났다. 남은 것은 **그것을 학생 노트북 60대에
올리는 일**이다.

실질 데드라인은 캠프일(9/19)이 아니라 **사전 온라인교육 시작일(9/14)** 이다.
그 2시간이 60대 설치를 지도할 수 있는 유일한 기회다.

## 2. 실측으로 확인된 사실 (2026-08-21)

설계 가정을 모두 실제로 확인했다.

| 항목 | 결과 |
|---|---|
| Windows 데스크탑 앱 존재 | `opencode-desktop-win-x64.exe` 121MB (릴리스 v1.18.20) |
| **코드 서명** | **유효함.** `CN="Anomaly Innovations, Inc", L=Dover, S=Delaware, C=US` |
| 조용한 설치 | `Start-Process -ArgumentList '/S' -Wait` → exit 0 |
| 설치 위치 | `%LOCALAPPDATA%\Programs\@opencode-aidesktop` (per-user, 관리자권한 불필요) |
| 앱 데이터 위치 | `%APPDATA%\ai.opencode.desktop` |
| 프리셋 인식 경로 | `~/.config/opencode` (환경변수 없이) — **에이전트 4/4, 명령어 10/10 로드 확인** |
| GUI 언어 | 한국어 (프로젝트/설정/도움말/세션 검색 등) |
| 프로젝트 등록부 | `%APPDATA%\ai.opencode.desktop\opencode.global.dat` → `server` 키 → `{"projects":{"local":[{"worktree":"<경로>"}]}}`. **평문 JSON** |
| 온보딩 건너뛰기 | `opencode.settings` → `{"firstLaunchOnboardingComplete": true}`. 평문 JSON |

**코드 서명이 이미 되어 있다는 것이 설계를 크게 바꿨다.** 인증서를 구매할
필요가 없고, 번들의 모든 구성요소(Node·Python·Git 공식 설치본도 서명됨)가
서명된 상태다. SmartScreen 대응이 설계 부담에서 빠졌다.

## 3. 확정 사항

| 결정 | 내용 |
|---|---|
| 학생이 보는 화면 | **opencode 데스크탑 앱** (터미널 아님) |
| 자체 IDE / 외부 IDE | **만들지 않고 쓰지 않는다.** 데스크탑 앱이 그 역할 |
| 배포 방식 | 사전배포(9/14~18 설치 지도) + 당일 미설치자 USB 구제 |
| 포함 구성요소 | opencode 데스크탑 · Node LTS · Python 3.12 · Git · Nerd Font · higgsfield CLI · 프리셋 · 키 |
| 제외 | VS Code (GUI 방식이라 학생이 쓸 일이 없음) · Docker · WSL · Java |
| 이번 범위 | **인스톨러 + 당일 런처** 둘 다 |

### VS Code 를 뺀 이유

주최측 질문("외부 IDE 쓰면 학생들이 AI agent 켜고 제어하기 힘들 것 같다")이
정확한 지적이다. 데스크탑 앱 안에 프로젝트·세션·에이전트가 다 들어 있어서
편집기를 따로 띄울 이유가 없고, 학생은 설계상 코드를 보지 않는다.
결과 확인은 `/보여줘`(브라우저)로 한다.

## 4. 구성

```
캠프설치_USB/  (또는 사전배포 ZIP)
├─ 설치하기.cmd                ← 학생이 더블클릭하는 단 하나
├─ 점검하기.cmd                ← 문제 생겼을 때 재실행 (멘토용)
├─ 캠프시작.cmd                ← 당일 아침 런처
├─ scripts/
│  ├─ orchestrator.ps1         ← 설치 순서 전체
│  ├─ selfcheck.ps1            ← 자체 점검 (4개 초록불)
│  ├─ launcher.ps1             ← 팀 폴더 생성 + 앱 등록
│  └─ lib-appstate.ps1         ← 데스크탑 앱 JSON 상태 읽기/쓰기
├─ bundle/
│  ├─ opencode-desktop-win-x64.exe
│  ├─ node-lts-x64.msi
│  ├─ python-3.12-amd64.exe
│  ├─ Git-64-bit.exe
│  ├─ CascadiaCode-NF.zip
│  └─ npm-offline/             ← higgsfield CLI 오프라인 캐시
├─ preset/                     ← 리포의 camp-preset 사본
├─ template/                   ← 리포의 template 사본
├─ secrets/
│  ├─ auth.json                ← DeepSeek (→ ~/.local/share/opencode/)
│  ├─ credentials.json         ← Higgsfield refresh_token (→ ~/.config/higgsfield/)
│  └─ config.json              ← Higgsfield workspace_id
└─ 학생용-치트시트.pdf
```

## 5. 설치 순서 (`orchestrator.ps1`)

1. **사전 점검** — Windows 10/11 x64, 여유 공간 5GB, 기존 설치 감지
2. **Mark-of-the-Web 해제** — `Get-ChildItem -Recurse | Unblock-File`.
   USB·다운로드 파일의 차단 플래그를 제거한다. 빼먹으면 60대에서 다 막힌다
3. **Node LTS** 조용히 설치 (`msiexec /i /qn ALLUSERS=0`)
4. **Python 3.12** 조용히 설치 (`/quiet InstallAllUsers=0 PrependPath=1`)
5. **Git** 조용히 설치 (`/VERYSILENT /NORESTART`)
6. **Nerd Font** per-user 설치 (`%LOCALAPPDATA%\Microsoft\Windows\Fonts` + 레지스트리 HKCU)
7. **opencode 데스크탑** 조용히 설치 (`/S`)
8. **higgsfield CLI** 오프라인 캐시에서 설치
9. **프리셋 배치** — `preset/` → `~/.config/opencode/` (기존 것이 있으면 백업)
10. **키 배치** — `secrets/` → 각 경로
11. **연습 프로젝트 등록** — `~/창의디자인캠프/연습/` 생성 후 앱 등록부에 추가,
    온보딩 건너뛰기 플래그 설정
12. **자체 점검 실행** (6절)
13. **로그 저장** — `~/창의디자인캠프/설치기록.txt`

각 단계는 실패해도 다음으로 넘어가지 않고 멈추며, 어느 단계에서 멈췄는지
한국어로 표시한다.

## 6. 자체 점검 (`selfcheck.ps1`) — 기계적으로 검증 가능

프리셋 로드를 "된 것 같다"가 아니라 **숫자로** 확인할 수 있다는 것이
이번 실측의 부수 성과다.

| 점검 | 방법 | 통과 조건 |
|---|---|---|
| 도구가 깔렸나 | `opencode --version` | `1.18.20` |
| **프리셋이 먹었나** | `opencode serve` 기동 후 `GET /agent`, `GET /command` | 에이전트 4개 + 명령어 10개 |
| AI 도우미가 붙나 | `opencode run "안녕" --agent 도우미` | 한국어 응답 수신 |
| 그림 만들기가 붙나 | `higgsfield account status` | 계정·잔액 출력 |

네 개가 모두 초록불이면 "준비 끝!" 화면, 하나라도 빨간불이면 그 항목의
한국어 조치 안내를 표시하고 로그 위치를 알려준다.

## 7. 당일 런처 (`캠프시작.cmd` → `launcher.ps1`)

팀 배정이 캠프 당일(9/19 09:30)이므로 설치 시점에는 팀 폴더를 만들 수 없다.
런처가 그 간극을 메운다.

1. 조 번호(1~15)와 팀 이름을 묻는다. **학생 이름은 묻지 않는다**
2. `new-team.sh` 와 동일한 규칙으로 `~/창의디자인캠프/NN조_팀명/` 생성
   (템플릿 복사 + `우리팀.md`·표지의 자리표시자 치환)
3. 데스크탑 앱 등록부에 그 폴더를 추가하고 첫 프로젝트로 지정
4. 데스크탑 앱 실행
5. 학생은 앱이 열리면 바로 `/시작` 을 입력하면 된다

런처는 두 번 실행해도 안전하다 (이미 있는 팀 폴더는 재사용).

## 8. 팀 협업 — 파일을 나눠 충돌을 없앤다

주최측 방침: 자체 Git 호스팅으로 팀장이 "합쳐줘" 하면 합친다.

여기에 **설계상 대비가 필요하다.** 4명이 같은 `index.html` 을 각자 고치면
Git 병합 충돌이 발생하고, 초5~중1이 충돌을 해결할 수는 없다.

따라서 학생 기여를 **파일 단위로 분리**한다.

```
NN조_팀명/
├─ index.html            ← 조립 결과물. 팀장 노트북에서만 생성
├─ slides/
│  ├─ 1번친구.html        ← 각자 자기 파일만 만든다
│  ├─ 2번친구.html
│  ├─ 3번친구.html
│  └─ 4번친구.html
├─ assets/
└─ 우리팀.md
```

- 각 학생은 자기 `slides/N번친구.html` 만 편집한다 → 충돌이 구조적으로 불가능
- `assets/` 는 파일명이 겹치지 않게 래퍼가 이미 번호를 붙인다
- 팀장이 "합쳐줘" 하면 `디자이너` 가 `slides/*.html` 을 읽어 `index.html` 로 조립
- 자체 Git 이 준비되면 그대로 얹으면 되고, 늦어지면 **USB 로 `slides/` 폴더만
  주고받아도 동일하게 동작한다**

이 구조는 자체 Git 완성 여부에 프로젝트가 종속되지 않게 한다.

## 9. 실패 대응

| 상황 | 대응 |
|---|---|
| 백신이 설치를 막음 | 설치 폴더 예외 추가 안내 화면. 안 되면 USB 구제 명단 등록 |
| 관리자권한을 요구함 | 전 구성요소를 per-user 설치로 지정했으므로 발생하지 않아야 함. 발생하면 로그로 원인 특정 |
| 디스크 부족 | 사전 점검에서 5GB 확인하고 미달 시 진행하지 않음 |
| 네트워크 없음 | 오프라인 번들이므로 설치는 진행됨. 자체 점검의 AI 항목 2개만 빨간불 → 네트워크 연결 후 `점검하기.cmd` 재실행 |
| 이미 opencode 를 쓰던 학생 | 기존 `~/.config/opencode` 를 타임스탬프 백업 후 설치 (프리셋 설치 스크립트가 이미 그렇게 동작) |
| 설치 중 중단 | 재실행하면 이미 설치된 구성요소는 건너뜀 (멱등) |

## 10. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 자체 Git 이 9/19까지 안 됨 | 팀 병합 경로 없음 | 8절의 파일 분리 구조 + USB 대체. 프로젝트가 Git 에 종속되지 않음 |
| 데스크탑 앱 등록부 형식이 버전마다 바뀜 | 프로젝트 사전 등록 실패 | 버전 고정(1.18.20). 등록 실패 시 앱은 정상 실행되고 학생이 폴더를 고르는 것으로 강등(graceful degradation) |
| 사전교육에 불참한 학생 | 당일 설치 필요 | USB + 멘토 1:1. 사전교육 때 불참자 명단 확정 |
| 학생 노트북 사양 미달 | 앱이 무거움 | 사전 점검에서 확인. Electron 앱이라 RAM 4GB 이상 권장 |
| 크레딧 소진 | 캠프 중 그림 생성 정지 | 주최측 충전 (선행 문서 참조). 잔액 200 이하 시 멘토가 즉시 보고 |

## 11. 성공 판정

- 초5 학생이 **혼자 인스톨러를 실행해 초록불 4개**까지 도달한다
- 설치에 걸리는 시간이 노트북 1대당 **10분 이내**
- 관리자 권한을 한 번도 요구하지 않는다
- 당일 런처 실행부터 `/시작` 입력까지 **2분 이내**
- 설치 실패 시 멘토가 로그만 보고 원인을 특정할 수 있다

## 12. 열린 질문

1. **자체 Git 호스팅 완성 시점** — 8절 구조로 종속성은 끊었지만, 팀장 병합
   흐름을 실제로 쓸 수 있는지는 그 일정에 달려 있다
2. **학생 노트북 사양 분포** — 사전교육 때 조사해야 한다 (RAM, OS 버전, x64/arm64)
3. **USB 개수** — 미설치자 규모에 따라. 사전교육 결과로 결정
4. **발표 환경** — 팀 노트북을 프로젝터에 직접 연결하는지. `/제출` 과 발표
   흐름에 영향 (선행 문서에서도 미해결)
