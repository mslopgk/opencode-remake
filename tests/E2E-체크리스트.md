## 확인하지 못한 것 (정직하게)

1. **`Read-Host` 프롬프트 상호작용** — 리다이렉트된 stdin 을 `Read-Host` 가
   읽지 않아 자동 검증이 불가능했다. `Start-CampLauncher -Number -Name` 인자
   경로로 우회 검증했다. **사람이 직접 타이핑해 한 번 확인해야 한다**
2. **아무 것도 설치되지 않은 깨끗한 노트북** — 이 PC 에는 Node·Python·Git 이
   이미 있었다. 전체 설치 경로와 실제 소요 시간은 미검증
3. **데스크탑 앱 GUI 안에서의 조작** — 앱이 열리고 프로젝트가 등록된 것까지
   확인했으나, 앱 화면에서 세션을 만들어 `/포스터` 를 눌러보는 것은
   GUI 자동화가 필요해 하지 않았다. 서버 API 로 동일 경로를 검증했다
4. **백신 차단** — 이 PC 의 백신 설정에서는 발생하지 않았다. 다른 노트북에서는
   발생할 수 있다

## 정리

개발 환경은 E2E 후 복원했다:
- `~/.config/opencode` → 원래 설정 복원
- 데스크탑 앱 상태(`opencode.global.dat`, `opencode.settings`) → 백업에서 복원
- 남긴 것: `%LOCALAPPDATA%\Programs\opencode-cli` (점검용 CLI), Cascadia 글꼴,
  `~/창의디자인캠프/` (연습·팀 폴더). 모두 무해하며 필요하면 지워도 된다

## 2차 E2E 에서 발견한 치명적 누락 (2026-08-22)

1차 E2E 가 초록불 4개로 통과했는데도 **학생은 그림을 만들 수 없는 상태였다.**

`/합쳐줘` 를 시험하다 발견했다. 에이전트가 `merge-slides.sh` 를 찾지 못하고
`find` 로 디스크를 헤매다 10분을 넘겼다. 파헤쳐 보니 원인이 하나가 아니었다.

| 문제 | 왜 놓쳤나 | 조치 |
|---|---|---|
| **인스톨러가 헬퍼 스크립트를 아예 배포하지 않았다** | 프리셋 E2E 가 테스트에서 `PATH` 를 직접 넣어줘서 통과했다 | `dist/tools/` 추가, `%LOCALAPPDATA%\Programs\camp-tools` 설치 + 사용자 PATH 등록 |
| 자체 점검에 도구 확인 항목이 없었다 | 점검 항목을 도구 관점이 아니라 설치 관점으로만 짰다 | 점검을 4개 → **5개**로. `Test-CampTools` 추가 |
| 명령어·스킬이 `PATH` 에 의존했다 | 개발 환경에는 PATH 가 있었다 | 전부 `$LOCALAPPDATA/Programs/camp-tools/...` 절대경로로 |
| 합치기를 LLM 이 직접 편집하게 했다 | 결정적 작업을 프롬프트에 맡겼다 | `merge-slides.sh` + `!`셸 주입`` 으로 (`/보여줘`·`/제출` 과 동일 패턴) |
| 글꼴 감지가 틀렸다 | Nerd Font 가 Cascadia → **CaskaydiaCove** 로 이름을 바꾼다 | 두 이름 다 확인. 사용 중 파일은 "이미 있음" 으로 처리 |
| 자체 점검이 명령어 10개만 셌다 | `합쳐줘` 를 추가하고 카운트를 안 고쳤다 | **11개**로 |

**교훈:** 초록불이 다 켜져도 학생이 실제로 쓸 수 없을 수 있다.
자체 점검 항목은 "설치했는가" 가 아니라 "학생이 그 기능을 쓸 수 있는가" 로
짜야 한다.

## 아직 사람이 한 번 확인해야 하는 것

`/합쳐줘` 의 **셸 주입이 데스크탑 앱 안에서 실제로 실행되는지**는 자동 검증하지
못했다. 슬래시 명령은 TUI/GUI 전용이고 `opencode run` 은 이를 파일 경로로
해석한다. `merge-slides.sh` 자체는 단위 테스트 21개로 검증됐고(1초에 완료),
셸 주입은 `/보여줘`·`/제출` 이 쓰는 것과 같은 이미 검증된 메커니즘이다.
**캠프 전에 앱에서 `/합쳐줘` 를 한 번 눌러 확인해야 한다.**
